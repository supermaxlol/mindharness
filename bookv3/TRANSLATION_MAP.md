# V3 translation map: familiar anchors with stopping points

Source maps consulted: `/Users/shehzad/Desktop/FAMOUS_ALLEGORIES_AS_FIVE_HOLD.md` and the three `research/LITERATURE_REVIEW*.md` files. They supply the book's allegories, sources, and cross-domain synthesis. V3 uses each study for what it establishes, then makes the book's larger inference through convergence and elimination. The familiar anchor gives the reader a decoding key for that inference.

## Three levels of anchor

**Whole book — the whirlpool, then the shared notebook.** The whirlpool gives the reader persistence through replacement; the notebook shows the decisive external step, when a stranger can inherit an entry, act on it, and try to amend it. The record then moves from a recipe to a balance sheet to a machine log; after synthesis, the reader applies the same test to a self-record. The final outlook asks whether future systems acquire a usable witness before they acquire more power. The legal, computational, and personal consequences must be established separately.

**Each chapter — one object, one failed expectation.** A chapter earns its technical idea by following what the object does and where a reasonable first explanation breaks.

**Each dense paragraph — anchor, link, source, boundary.** Put only one new technical distinction in the paragraph. Supply a measured value only when it changes the reader's understanding of the scene; otherwise place it in a note. The source must support the exact claim, not merely be adjacent to it.

The Chinese-page example gives the governing limit: **marks need a learned decoder, but the decoder is not free to make the marks mean anything.** Language conventions and context constrain the interpretation. In the book, “meaning lives in the reader” names the reader's active work; it is not a claim that texts, shared conventions, or institutions have no role.

## One-paragraph rule

**Anchor → link → finding → boundary → consequence.** Example: “The checking code behaved like a phone app that displayed ‘synced’ while saving to the wrong account. In the S126 test, records were written to one ledger and the checker read a separate empty ledger. The intended comparison therefore could not test whether the record improved the model's answer. A phone sync indicator is only an analogy; the documented fact is the code path. The next version must test the same subject with a veridical, shuffled, and absent ledger that it can actually read.”

The anchor reduces learning cost. The boundary protects the fact.
